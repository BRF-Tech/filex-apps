# filex-convert: the conversions its store listing declares

Generated by `scripts/gen-convert-conversions.sh` from filex-convert **v0.2.0** (commit `a11dd275478e881de34fc07a8854f9dfc790929d`); do not edit by hand.
`listing.json`'s `conversions` (106 entries, 2148 source-target-condition pairs) is written by the same run.

How it is measured: for every format the converter detects and every other format, the converter's own planner
(`graph.Route`, the call its wizard makes for the target list) is asked whether a route exists with a given set
of filex engines present. A pair is declared with no `needs` when it works with no engine at all (pure Go in the
sandbox), else once per smallest set of engines that is enough (`pdf -> png` needs poppler, or ghostscript).
A format converted to itself (PDF compression, re-encoding) is not declared. Routes chain at most 3 steps,
so `docx -> pdf` is declared without `needs`: with nothing connected it goes through the sandbox's own Word
reader and PDF writer (text and tables); with ONLYOFFICE connected the planner prefers it for the layout.
The archive targets (zip, tar, tar.gz, tar.zst, tar.xz) of a non-archive format are the converter's "pack this
file into an archive" step. `needs` lists engine ids as filex names them (the manifest's `engines:<id>`
permissions): office is the ONLYOFFICE Document Server connected to filex, the others are programs on the
filex server.
